# Nginx 節點建置操作手冊（Ubuntu Server 26.04 LTS / vSphere）

本文件記錄從 vSphere 建立 VM、安裝 Ubuntu Server 26.04.1 LTS、安裝 Nginx，到把節點接入「Nginx HA Proxy Manager」並上傳 SSL 憑證的完整步驟。第二台以後的節點照同一流程做，只更換主機名稱與 IP。

> 本文件會進版控，所有 IP、網域、帳號一律以 `<尖括號>` 表示，請代入實際值，**不要把真實 IP、密碼、私鑰寫進本檔**。

---

## 0. 事前準備

### 0-1 向網管取得網路資料

| 項目 | 代號 | 說明 |
|---|---|---|
| 節點固定 IP | `<節點IP>` | 例：x.x.x.91 |
| 網段（CIDR） | `<網段>/<前綴>` | 遮罩 255.255.255.192 = `/26`，網段為 IP 所屬的起始位址 |
| 預設閘道 | `<閘道>` | |
| DNS | `<DNS1>,<DNS2>` | 逗號分隔 |
| 主機名稱 | `nginx-node1`、`nginx-node2`… | 需與系統「Nginx 節點」的節點名稱對應 |

> 遮罩換算：255.255.255.0 = /24、255.255.255.128 = /25、255.255.255.192 = /26、255.255.255.224 = /27。

### 0-2 VM 規格（建議）

| 項目 | 建議值 | 備註 |
|---|---|---|
| Guest OS | Ubuntu Linux (64-bit) | |
| CPU / 記憶體 | 2 vCPU / 2 GB 以上 | 純反向代理用量很低 |
| 硬碟 | 20 GB 以上，Thin Provision | |
| 網卡 | VMXNET3，接在節點所屬的 VLAN / Port Group | |
| CD/DVD | 掛載 `ubuntu-26.04.1-live-server-amd64.iso`，勾 Connect at power on | |

## 1. 安裝 Ubuntu Server

在 vSphere Client 選取 VM → **LAUNCH WEB CONSOLE**。

> **Web Console 注意事項**
> - 先按右上角 **Enforce US Keyboard Layout**，避免符號打錯。
> - 安裝程式**只能用鍵盤操作**（方向鍵、Tab、Enter、空白鍵），滑鼠點擊無效。
> - Console 打字時**大寫字母與需按 Shift 的符號可能遺失**。安裝時的密碼建議先用「小寫英文 + 數字」，裝好後用 SSH 執行 `passwd` 改成正式密碼。

| 步驟 | 畫面 | 操作 |
|---|---|---|
| 1 | GNU GRUB | 選 **Try or Install Ubuntu Server** → Enter |
| 2 | Language | **English**（主控台無法顯示中文） |
| 3 | Keyboard configuration | Layout / Variant 都是 **English (US)** → Done |
| 4 | Type of installation | **Ubuntu Server**（不要選 minimized）；第三方驅動不勾 → Done |
| 5 | Network configuration | 見 1-1 |
| 6 | Proxy configuration | 留空 → Done（除非學校網路需經 Proxy 才能上網） |
| 7 | Ubuntu archive mirror | 預設（`tw.archive.ubuntu.com`），出現 `This mirror location passed tests.` → Done。**能通過測試代表網路設定正確** |
| 8 | Guided storage | **Use an entire disk**，勾 **Set up this disk as an LVM group**，不加密 → Done |
| 9 | Storage configuration | 見 1-2（把 `/` 調到最大） |
| 10 | Confirm destructive action | **確認是正確的 VM 後**選 Continue（會清空整顆硬碟） |
| 11 | Profile configuration | Your name：`System Admin`；Server name：`nginx-node1`；Username：`sysadmin`；密碼見上方注意事項 |
| 12 | Upgrade to Ubuntu Pro | **Skip for now** → Continue |
| 13 | SSH configuration | **用空白鍵勾選 Install OpenSSH server**（必勾） → Done |
| 14 | Featured server snaps | 全部不勾 → Done |
| 15 | Installing system | 等待約 3–5 分鐘，標題變成 **Installation complete!** |
| 16 | Reboot Now | 選 Reboot Now；出現 `Please remove the installation medium, then press ENTER` 直接按 Enter |
| 17 | 開機完成 | 出現 `nginx-node1 login:` 即安裝完成 |

### 1-1 網路設定（固定 IP）

1. 用方向鍵選到網卡（例如 `ens33`）→ Enter → **Edit IPv4**。
2. IPv4 Method 選 **Manual**，依序填入：

| 欄位 | 填入 |
|---|---|
| Subnet | `<網段>/<前綴>`（例：x.x.x.64/26） |
| Address | `<節點IP>` |
| Gateway | `<閘道>` |
| Name servers | `<DNS1>,<DNS2>` |
| Search domains | 留空 |

3. Save，確認網卡下方顯示 `static <節點IP>/<前綴>` → Done。

### 1-2 把根目錄 `/` 調到最大

安裝程式預設只把約一半空間給 `/`，其餘留在 `free space`。

1. 在 **USED DEVICES** 下選 `ubuntu-lv` → Enter → **Edit**。
2. Size 欄位改成括號中的最大值（例：`Size (max 146.945G)` 就填 `146.945G`）。
3. Save，確認 FILE SYSTEM SUMMARY 的 `/` 已變成最大值、AVAILABLE DEVICES 顯示 `No available devices`。

> 忘了調也可以裝完再補：`sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv`

### 1-3 記下主機指紋

第一次開機時畫面會印出 SSH 主機金鑰，找 `ED25519` 那段的 `The key fingerprint is: SHA256:...`，記下來供第 5 節比對。

## 2. 從管理主機（Windows）連線

開 PowerShell，先確認 SSH port 可連：

```powershell
Test-NetConnection <節點IP> -Port 22
```

`TcpTestSucceeded : True` 後登入（第一次會問 `yes/no`，輸入 `yes`）：

```bash
ssh sysadmin@<節點IP>
```

若安裝時用的是臨時密碼，登入後立刻改掉：

```bash
passwd
```

---

## 3. 產生部署金鑰（只需做一次，所有節點共用）

在**管理主機（跑本系統的 Windows）**的 PowerShell 執行：

```powershell
New-Item -ItemType Directory -Force C:\nginx-ha-manager\keys
ssh-keygen -t ed25519 -C "nginx-ha-manager" -f C:\nginx-ha-manager\keys\deployer_ed25519
```

passphrase 直接按兩次 Enter 留空（若有設，需填入 `backend/.env` 的 `SSH_KEY_PASSPHRASE`）。

顯示公鑰，整行複製（第 4 節要用）：

```powershell
Get-Content C:\nginx-ha-manager\keys\deployer_ed25519.pub
```

> 私鑰 `deployer_ed25519`（沒有 `.pub`）**絕對不可外流或放進 git**。已經產生過就不要重做，否則已上線的節點都要換公鑰。

## 4. 節點初始化腳本

以 `sysadmin` 登入節點後，把下面整段貼上執行。**先把 `PUBKEY=` 那行換成第 3 節複製的公鑰**。中途會要求輸入一次 sudo 密碼，約 2–5 分鐘完成。

```bash
cat > ~/node-setup.sh <<'EOF'
#!/bin/bash
# Nginx HA Proxy Manager 節點初始化（Ubuntu 26.04）
set -euo pipefail

PUBKEY='ssh-ed25519 AAAA...（換成管理主機的公鑰）... nginx-ha-manager'
export DEBIAN_FRONTEND=noninteractive

echo "== 1. 時區 =="
timedatectl set-timezone Asia/Taipei

echo "== 2. 系統更新 + 安裝 nginx / open-vm-tools =="
apt-get update
apt-get -y full-upgrade
apt-get -y install nginx open-vm-tools

echo "== 3. 防火牆 =="
ufw allow OpenSSH
ufw allow 80,443/tcp
ufw --force enable

echo "== 4. deployer 帳號（僅金鑰登入）=="
id deployer >/dev/null 2>&1 || useradd -m -s /bin/bash deployer
usermod -p '*' deployer
install -d -m 700 -o deployer -g deployer /home/deployer/.ssh
echo "$PUBKEY" > /home/deployer/.ssh/authorized_keys
chown deployer:deployer /home/deployer/.ssh/authorized_keys
chmod 600 /home/deployer/.ssh/authorized_keys

echo "== 5. 系統管理目錄 =="
install -d -m 755 -o deployer -g deployer /etc/nginx/sites-managed
install -d -m 750 -o deployer -g deployer /etc/nginx/ssl

echo "== 6. nginx.conf 加入 sites-managed =="
if ! grep -q 'sites-managed/\*\.conf' /etc/nginx/nginx.conf; then
  cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak
  sed -i '/include \/etc\/nginx\/sites-enabled\/\*;/a\        include /etc/nginx/sites-managed/*.conf;' /etc/nginx/nginx.conf
fi
grep -q 'sites-managed/\*\.conf' /etc/nginx/nginx.conf || { echo "!! include 加入失敗，請手動檢查 nginx.conf"; exit 1; }
rm -f /etc/nginx/sites-enabled/default

echo "== 7. sudoers（只允許 nginx -t 與 reload）=="
cat > /tmp/nginx-deployer <<'SUDO'
deployer ALL=(root) NOPASSWD: /usr/sbin/nginx -t
deployer ALL=(root) NOPASSWD: /usr/bin/systemctl reload nginx
SUDO
visudo -cf /tmp/nginx-deployer
install -m 440 -o root -g root /tmp/nginx-deployer /etc/sudoers.d/nginx-deployer
rm -f /tmp/nginx-deployer

echo "== 8. 驗證 =="
nginx -t
systemctl enable --now nginx
systemctl reload nginx
nginx -v
sudo -u deployer sudo -n /usr/sbin/nginx -t && echo "deployer 免密碼 sudo：OK"
ufw status
echo "主機指紋："
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
echo "===== 全部完成 ====="
EOF
sudo bash ~/node-setup.sh
```

### 腳本做了什麼

| 項目 | 結果 |
|---|---|
| 時區 | Asia/Taipei（部署紀錄時間才正確） |
| 套件 | 系統全面更新；安裝 `nginx`、`open-vm-tools`（vSphere 的「未安裝 VMware Tools」警告會消失） |
| 防火牆 | 只開 SSH(22)、80、443 |
| `deployer` 帳號 | 無密碼、只能用金鑰登入 |
| 目錄 | `/etc/nginx/sites-managed`（755）、`/etc/nginx/ssl`（750），擁有者皆為 deployer |
| nginx.conf | 在 `http {}` 內 `sites-enabled` 下一行加入 `include /etc/nginx/sites-managed/*.conf;`，原檔備份為 `nginx.conf.bak` |
| 預設網站 | 移除 `sites-enabled/default`（Welcome to nginx 頁面會消失，屬正常） |
| sudo 權限 | deployer 只能免密碼執行 `nginx -t` 與 `systemctl reload nginx`（26.04 的 sudo 為 sudo-rs，語法相同） |

看到 `===== 全部完成 =====` 即成功。腳本可重複執行。

## 5. 從管理主機驗證

在 Windows PowerShell 執行（以 deployer + 金鑰登入，全程不應要求密碼）：

```powershell
ssh -i C:\nginx-ha-manager\keys\deployer_ed25519 deployer@<節點IP> "sudo -n /usr/sbin/nginx -t; sudo -n /usr/bin/systemctl reload nginx && echo RELOAD_OK; systemctl is-active nginx; nginx -v; ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub"
```

預期結果：

```
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
RELOAD_OK
active
nginx version: nginx/1.28.x (Ubuntu)
256 SHA256:xxxxxxxx root@nginx-node1 (ED25519)
```

- 最後一行指紋要與第 1-3 節在 console 上記下的**完全一致**，不一致代表連到的不是這台主機，**不可繼續**。
- Nginx ≥ 1.25.1，`backend/.env` 的 `NGINX_HTTP2_SYNTAX` 維持 `modern`。

## 6. 接入管理系統

### 6-1 設定私鑰路徑（只需做一次）

編輯 `backend/.env`（路徑用正斜線）：

```ini
SSH_KEY_PATH=C:/nginx-ha-manager/keys/deployer_ed25519
```

修改後重新啟動後端（`npm run start`）。

### 6-2 登錄節點

1. 開啟 `http://localhost:<PORT>` 並登入。
2. 切到 **Nginx 節點** 分頁，新增或編輯節點：

| 欄位 | 填入 |
|---|---|
| 節點名稱 | `nginx-node1` |
| IP | `<節點IP>` |
| SSH Port | 22 |
| SSH 帳號 | `deployer` |
| 私鑰路徑 | 留空（使用 `.env` 的 `SSH_KEY_PATH`） |
| 主機指紋 | 按「從主機讀取」，**與第 5 節的指紋比對一致才儲存** |
| 啟用 | 是 |

3. 按上方 **重新檢測**，燈號變綠（`ONLINE / nginx: active`）即完成。

> **尚未建好的節點請先停用**（取消「啟用」）。部署時只要任一啟用中的節點 `nginx -t` 失敗或連不上，整批部署就會中止並回滾。

## 7. 上傳 SSL 憑證

### 7-1 要用哪些檔案

憑證商提供的資料夾通常包含多種格式，本系統只需要以下**其中一組**：

| 方式 | 檔案 | 說明 |
|---|---|---|
| **A（建議）** | `nginx\<名稱>_fullchain.crt` + `nginx\<名稱>.key` | 不需密碼 |
| B | `<名稱>-IIS.pfx` + PFX 密碼 | 系統會自動拆成 fullchain 與私鑰 |

**不要用**：只有葉憑證的 `<名稱>.crt`（會出現「檔案僅含葉憑證、未包含中繼憑證」警告）、單獨的中繼 / 根憑證 `.cer`、IIS 安裝腳本。

上傳前可用 OpenSSL 自行確認（只讀公開資訊）：

```bash
# fullchain 應包含 2 張以上憑證
grep -c 'BEGIN CERTIFICATE' <名稱>_fullchain.crt
# 涵蓋網域與到期日
openssl x509 -in <名稱>_fullchain.crt -noout -subject -enddate -ext subjectAltName
```

### 7-2 上傳步驟

1. **SSL 憑證庫** 分頁 → **上傳憑證**。
2. 憑證別名：例如 `*.<網域> <年月> 續約`。
3. 上傳模式選 **.crt (Fullchain) + .key**，憑證檔選 `_fullchain.crt`，私鑰檔選 `.key`。
4. 上傳並驗證。成功時顯示到期日且**沒有警告**；系統會自動比對公私鑰，不匹配會直接拒絕。

> - 上傳後憑證只存在系統內，要到 **網域對照規則** 綁定憑證並**部署**後才會推送到各節點的 `/etc/nginx/ssl/`。
> - 若誤傳了只有葉憑證的檔案，在該筆按 **更新憑證** 重新選 fullchain 即可。
> - 續約時同樣用 **更新憑證**，已綁定的規則會一起換新。

### 7-3 憑證檔案保管

- 私鑰、PFX 與 PFX 密碼不要放在同一個雲端同步資料夾；密碼請移到密碼管理工具保存。
- 確認存放憑證的 OneDrive / 共用資料夾沒有對外分享連結。

## 9. 建置第二台節點

1. 重做第 1 節（主機名稱改 `nginx-node2`、IP 改第二台的 IP）。
2. 重做第 2、4、5 節。**第 3 節不用重做**，腳本中的 `PUBKEY` 用同一把公鑰。
3. 第 6-2 節在系統中編輯 `nginx-node2`：填 IP、讀取並比對指紋、**重新勾選啟用**。

> 若第二台是直接**複製第一台 VM** 產生的，兩台的 SSH 主機金鑰會相同，必須在第二台重新產生後再讀指紋：
> ```bash
> sudo rm /etc/ssh/ssh_host_* && sudo dpkg-reconfigure openssh-server && sudo systemctl restart ssh
> ```
> 同時需修改主機名稱（`sudo hostnamectl set-hostname nginx-node2`）與 `/etc/netplan/` 內的 IP。全新安裝較不易出錯。

## 10. 常見問題

| 狀況 | 原因 / 處理 |
|---|---|
| 安裝程式中滑鼠點了沒反應 | 安裝程式只吃鍵盤，用方向鍵 / Tab / Enter |
| 在 console 輸入的大寫變小寫 | Web Console 送 Shift 不穩；先用小寫密碼，裝好後 SSH 執行 `passwd` 修改 |
| Mirror 測試失敗 | 固定 IP / 閘道 / DNS 填錯，或該 VLAN 無法對外，按 Back 回網路設定檢查 |
| `Test-NetConnection` 22 port 失敗 | 安裝時沒勾 OpenSSH server；或防火牆 / VLAN ACL 擋住 |
| 金鑰登入仍要求密碼 | `.ssh` 須為 700、`authorized_keys` 須為 600，擁有者都是 deployer；公鑰需整行貼上 |
| `sudo -n` 出現 `a password is required` | sudoers 裡的路徑需與 `which nginx`、`which systemctl` 一致 |
| 系統燈號黃燈 | SSH 正常但 nginx 沒在跑：`sudo systemctl start nginx` |
| 系統燈號紅燈且訊息含 `ENOENT ... deployer_ed25519` | `.env` 的 `SSH_KEY_PATH` 路徑錯誤，或修改後沒重啟後端 |
| 指紋不一致 | 連到的不是預期主機，或主機重灌 / 複製過；確認後重新讀取指紋 |
| 上傳憑證出現「請選擇 .crt 與 .key 檔案」 | 舊版前端的檔案選擇問題，更新程式後按 Ctrl+F5 重新整理 |
| 上傳憑證出現「僅含葉憑證」警告 | 選到 `<名稱>.crt`，請改選 `<名稱>_fullchain.crt` |
| vSphere 顯示「未安裝 VMware Tools」 | `sudo apt install open-vm-tools`（初始化腳本已包含） |
