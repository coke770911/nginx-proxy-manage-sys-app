## 1. 系統概述

### 1.1 用途

本系統是校園網站的**反向代理集中管理平台（控制層）**。管理員在網頁上維護「網域 → 後端伺服器」對照規則與 SSL 憑證，按下「一鍵同步部署」後，系統以 SSH 把設定平行推送到多台 Nginx 節點，**全部節點檢查通過才生效，任一台失敗就全部回滾**。

### 1.2 解決的問題

| 過去 | 導入後 |
|---|---|
| 每個系統各自裝憑證，到期時逐台更換 | 憑證集中上傳一次，部署時自動推送到所有節點 |
| 每台 Nginx 手動編輯設定，兩台容易不一致 | 設定由系統產生，兩台完全相同 |
| 改錯設定可能讓網站全掛 | 部署前所有節點先 `nginx -t` 檢查，失敗自動回滾 |
| 看不到真實來源 IP，攻擊無從追查 | PROXY protocol 還原真實 IP，搭配 WAF 與 IP 存取控制 |
| 後端單點故障 | 一個網域可對應多台後端，自動故障切換 |

### 1.3 核心功能一覽

| 功能 | 重點 |
|---|---|
| 反向代理與 SSL 卸載 | 網域對應後端、TLS 1.2 / 1.3、HTTP/2、強制 HTTPS、維護中頁面 |
| SSL 憑證集中管理 | PEM / PFX 上傳、自動驗證與排憑證鏈、到期提醒 |
| 負載平衡 | 多台後端、權重、備援、Cookie 固定 |
| WAF 網站防火牆 | ModSecurity v3 + OWASP CRS，偵測 / 阻擋、排除誤判規則 |
| IP 存取控制 | 全域黑名單、網域只允許 / 拒絕清單、IP 群組、WAF Log 一鍵封鎖 |
| 維運輔助 | 節點資源監控、後端連線燈號、Nginx Log 檢視、切換前檢查、操作紀錄 |

## 2. 系統架構

### 2.1 流量路徑

```
          ① 查詢 portal.example.edu.tw
使用者 ─────────────────────────────→ DNS 伺服器
   ↑    ② 回覆 A 記錄 = <F5 VIP>          │
   └─────────────────────────────────────┘
   │
   │ ③ HTTPS 連線到 <F5 VIP>
   ▼
F5 負載平衡器 ──→ Nginx 節點 ×2 ──HTTP──→ 後端伺服器（可多台）
(L4 轉送，         │ ④ SSL 卸載
 PROXY protocol)   │ ⑤ IP 存取控制（全域黑名單 → 網域清單）
                   │ ⑥ WAF（ModSecurity + OWASP CRS）
                   │ ⑦ 負載平衡轉送到後端
                   ↑
      本系統（控制層）：以 SSH / SFTP 推送設定與憑證
```

- **DNS**：使用者先查詢網域，DNS 回覆 F5 VIP 的位址，瀏覽器才連到 F5。所有經本系統代理的網域，A 記錄都指向同一個 F5 VIP；F5 與 Nginx 再依 SNI / Host 分辨是哪個網域。網域要改由本系統代理時，就是把它的 A 記錄從原本的後端 IP 改成 F5 VIP（改之前先做「切換前檢查」，見 3.8）。DNS 只對應名稱與 IP，無法依 port 分流。
- **F5**：使用者連線的入口（VIP），只做第四層轉送、不解密，把連線分給兩台 Nginx 節點，並以 PROXY protocol 帶上真實來源 IP。
- **Nginx 節點**：負責解密 HTTPS、IP 過濾、WAF 檢查，再轉送到後端。兩台設定完全相同，任一台故障由 F5 自動移除。
- **後端伺服器**：只需提供 HTTP，不必安裝憑證。
- **控制層（本系統）**：不在使用者流量路徑上，只負責產生與推送設定。本系統故障不影響網站運作。

### 2.2 控制層組成

```
瀏覽器（Vue 3 管理介面）
    │ HTTPS / JWT
    ▼
Node.js + Express（單一 port，同時提供前端靜態檔與 API）
    ├─→ SQL Server：規則、憑證、節點、帳號、紀錄
    ├─→ 學校認證 REST API（HTTPS + API 金鑰）：驗證登入帳密、查詢姓名與單位
    └─→ Nginx 節點（SSH 22，deployer 帳號）：部署、健康檢查、讀取 Log
```

### 2.3 技術組成

| 層級 | 技術 |
|---|---|
| 前端 | Vue 3、Vite、Element Plus |
| 後端 | Node.js（建議 22 / 24 LTS）、Express、Sequelize（mssql / tedious）、JWT、ssh2 |
| 資料庫 | Microsoft SQL Server |
| 認證 | 學校認證 REST API（帳密驗證 + 姓名 / 單位查詢）+ 可登入名單 |
| 節點 | Ubuntu Server 26.04、nginx 1.28、ModSecurity v3、OWASP CRS |
| 執行環境 | Windows Server 2022 + PM2（常駐與自動重啟） |

## 3. 功能說明

### 3.1 網域對照規則

每條規則代表一個對外網域，主要欄位：

| 欄位 | 說明 |
|---|---|
| 來源網域 | 例 `portal.example.edu.tw`，可用萬用字元 `*.example.edu.tw` |
| 網域別名 | 選填，一行一個（最多 50 個），例 `www.portal.example.edu.tw`；與來源網域共用所有設定。憑證必須涵蓋所有別名，且任一名稱只能屬於一條規則 |
| 後端主機 | 一台或多台 `IP:Port`，可設權重、備援、停用 |
| 分配方式 | 輪流（預設）/ 最少連線 / 依 Cookie 固定 |
| SSL 憑證 | 從憑證庫選擇；新增時可自動挑選涵蓋該網域、到期日最晚的憑證 |
| 強制 HTTPS | HTTP 請求以 301 轉到 HTTPS |
| WebSocket | 開啟升級連線支援 |
| 上傳上限 | `client_max_body_size`，預設 `2M` |
| 維護中頁面 | 開啟後回 HTTP 503 維護頁 |
| WAF 模式 | 關閉 / 僅偵測 / 阻擋，及排除規則 ID |
| IP 存取控制 | 不限制 / 只允許清單 / 拒絕清單 |
| 自訂 Nginx 語法 | 進階用途，插入 443 server 區塊 |
| 備註 | 任意文字 |
| 網域名稱申請單 | 申請單位、申請人、職稱、分機、Email（申請日期以規則建立日期為準）；新增規則時申請單位與申請人必填。只存在資料庫，不寫入 Nginx 設定 |

清單功能：

- 搜尋框可用網域或後端 IP / Port 即時過濾，表格右上角顯示筆數。
- 「建立日期」「最後更動」可排序；最後更動下方顯示「N 天沒變動」，超過 180 天以橘色標示。
- 來源網域為超連結，點擊另開視窗；有別名時旁邊顯示「+N 個別名」，點開可逐一開啟。搜尋也比對別名。
- 別名不會造成轉址迴圈：強制 HTTPS 轉址與轉給後端的 Host 都沿用使用者輸入的名稱（`$host`）。
- 為避免誤按，**刪除按鈕只在編輯視窗內**（左下角「刪除此規則」）。
- 支援 CSV 批次匯入 / 匯出（單次最多 500 列），匯入前會逐列檢查並預覽新增 / 覆蓋 / 略過；申請單欄位也包含在內。
- 「申請單」欄顯示申請單位與申請人，未填顯示「未填申請單」；可勾選「只看未填申請單」找出待補的規則。
- 「列印申請單」：勾選的規則（未勾選則為目前列表）每條產生一頁 A4 申請單，含申請人資料、網域設定與簽章欄，列印視窗選「另存為 PDF」即可一次存檔。

> 所有規則變更只寫入資料庫，**按「一鍵同步部署」後才會推送到節點**。

### 3.2 SSL 憑證集中管理

- 支援 **PEM（憑證 + 私鑰）** 與 **PFX** 上傳；自動驗證公私鑰是否相符、排好完整憑證鏈，並解析涵蓋網域與到期日。
- 清單顯示剩餘天數：60 / 30 / 14 天內分別以藍 / 橘 / 紅標示。
- 續約時直接更新同一張憑證，所有綁定的網域一起換新。
- 仍被規則使用的憑證不能刪除。
- 私鑰不會出現在 API 回應或操作紀錄中。

### 3.3 負載平衡

```
使用者 → F5 ─┬→ Nginx 節點 1 ─┬→ 後端 A
             └→ Nginx 節點 2 ─┴→ 後端 B
        F5 分流到兩台節點        節點依規則分流到多台後端
```

| 設定 | 說明 |
|---|---|
| 權重 1–100 | 數字越大分到越多流量 |
| 備援 | 主要後端都失效時才使用 |
| 停用 | 暫時下線維護，不寫入設定 |
| 輪流 / 最少連線 / 依 Cookie 固定 | 需要 Session 的系統建議用 Cookie 固定（例 `JSESSIONID`） |

- **故障切換**：10 秒內失敗 3 次即暫停該台 10 秒；連線失敗、逾時或 502 / 503 / 504 會自動改送下一台。
- 不提供「依來源 IP 固定」，避免 F5 SNAT 時全部流量落到同一台。

### 3.4 自訂錯誤頁

所有頁面都內嵌在 Nginx 設定中，不需要額外的圖檔，支援深色模式與手機版面。

| 狀態碼 | 情境 | 頁面 |
|---|---|---|
| 503 | 規則開啟「維護中頁面」 | 戴安全帽的土撥鼠 |
| 502 | 後端連不上（拒絕連線、主機不通） | 柴犬拿放大鏡 |
| 504 | 後端逾時沒有回應 | 柴犬拿放大鏡 |
| 404 | 直接以節點 IP 連線，或網域沒有對應規則（預設站台） | 柴犬拿放大鏡 |
| 400 / 403 / 404 / 405 / 408 / 410 / 429 / 500 / 501 / 503 | 後端回該狀態碼，且規則的「攔截後端錯誤」有勾選（預設都不勾；後端為 API 或有自訂錯誤頁時勿勾） | 柴犬拿放大鏡 |
| 403 | 被 IP 存取控制擋下，頁面顯示對方 IP | 柴犬拿放大鏡 |
| 403 | WAF「阻擋」模式擋下請求，頁面顯示事件編號、發生時間與對方 IP | 柴犬拿放大鏡 |

- 「攔截後端錯誤」有勾選任一項時，後端自己回的 502 / 504 也會改用系統頁；沒勾選的狀態碼照常顯示後端自己的頁面。
- WAF 攔截頁的**事件編號**就是 WAF Log 裡的 `unique_id`，使用者回報時，到「節點 Log → WAF」以事件編號當關鍵字搜尋，就能找到命中的規則 ID，再判斷是否為誤判。

`/f5-health-check` 在所有站台（包含維護中與預設站台）一律回 200，F5 健康檢查不受影響。

### 3.5 WAF 網站防火牆

- 使用 **ModSecurity v3 + OWASP 核心規則集（CRS）**，在 Nginx 解開 SSL 後檢查請求，阻擋 SQL 注入、XSS、路徑穿越、遠端指令執行、掃描器等攻擊。
- **全域設定**（「WAF 防護」分頁）：總開關、嚴格程度（1–4，建議 1）、阻擋門檻分數（預設 5）。
- **網域設定**：WAF 模式（關閉 / 僅偵測 / 阻擋）與排除規則 ID（處理誤判）。
- **設定優先順序**：總開關 → 網域維護模式 → 網域 WAF 模式 → 全域嚴格程度 → 網域排除規則 ID → 全域門檻。
- **事件查詢**：節點上的 `waf.log`（全部網域）與 `waf-<網域>.log`（單一網域），可在管理介面「檢視 Nginx Log」→「WAF 事件」查看；橘色為命中規則、紅色為已阻擋。
- **建議導入順序**：全部網域先「僅偵測」觀察 1–2 週 → 排除誤判 → 逐站改為「阻擋」。

詳細操作見 [`WAF防護操作手冊.md`](WAF防護操作手冊.md)。

### 3.6 IP 存取控制

| 層級 | 設定位置 | 作用 |
|---|---|---|
| 全域黑名單 | 「IP 存取控制」分頁 | 清單內的 IP / 網段連任何網域都回 403 |
| 網域清單 | 網域規則編輯視窗 | 只允許清單（例：後台只開放校內網段）或拒絕清單 |
| IP 群組 | 「IP 存取控制」分頁 | 把常用網段取名（例 `@校內網段`），多處引用，改一次全部生效 |
| WAF Log 一鍵封鎖 | 檢視 Nginx Log → WAF 事件 | 把攻擊來源 IP（或 /24 網段）加入全域黑名單或網域拒絕清單 |

- **判斷順序**：全域黑名單 → 網域清單 → WAF → 轉送後端。
- 支援 IPv4 / IPv6 與 CIDR；拒絕 `0.0.0.0/0` 等全開設定。
- 防呆：被引用中的群組不能刪除、改名或清空；引用不存在的群組時拒絕儲存並中止部署；只允許清單展開後若為空，一律拒絕。

### 3.7 真實來源 IP（PROXY protocol）

F5 做 SNAT 時，Nginx 看到的來源都是 F5。啟用 PROXY protocol 後：

- 節點另外監聽 `8080` / `8443`（帶 PROXY 標頭），F5 pool 改指到這兩個埠。
- 只採信 `.env` 中 `PROXY_PROTOCOL_FROM` 所列 F5 位址送來的標頭。
- 還原後的真實 IP 會用於 access log、WAF、IP 存取控制，並以 `X-Real-IP` / `X-Forwarded-For` 傳給後端。
- 原本的 80 / 443 保留，作為直連測試與 F5 健康檢查用。

### 3.8 切換前檢查

把網域的 DNS 改指 F5 VIP **之前**，先模擬切換後的連線結果（全程唯讀）：

| 檢查項目 | 失敗 / 警告條件 |
|---|---|
| DNS 現況 | 顯示是否已指向 VIP |
| 經 VIP 走 HTTPS（多次） | 連線失敗、5xx；各次結果不一致為警告 |
| 落到 404 預設頁 | 節點沒有此網域規則或尚未部署 |
| 轉址迴圈 | 後端自己強制 HTTPS（應改依 `X-Forwarded-Proto` 判斷） |
| 憑證 | 不涵蓋網域 |
| 經 VIP 走 HTTP | 開了強制 HTTPS 卻沒有 301 |
| 與現行路徑比對 | 狀態不同或頁面大小差超過 10% |
| 各節點直連 | 某台未部署或回 502 / 504 |

- 使用方式：單筆按該列的準心圖示；批次勾選多筆後按工具列「切換前檢查（N）」（一次最多 50 筆）。
- 結果分為「可以切換 / 有警告 / 不要切換 / 略過」。
- **需人工確認的項目**：後端是否以來源 IP 限制存取、網頁是否寫死 IP、頁面中的 JavaScript 轉址（命令列檢查不會執行 JavaScript，建議切換前實際以瀏覽器開啟入口頁面）。

### 3.9 維運輔助功能

| 功能 | 說明 |
|---|---|
| 節點卡片 | 連線燈號、CPU（含核心數）、RAM、硬碟使用率、已開機時間，以及 OS、nginx、ModSecurity、CRS 版本 |
| 套件 / OS 更新偵測 | 節點卡片顯示可更新套件數（含安全性更新數，點開看清單）、「需要重開機」、「新版 Ubuntu」；唯讀、每 30 分鐘檢查一次，按「重新檢測」立即更新 |
| 更新套件 | 節點卡片「更新套件」按鈕，在節點背景執行 apt update + full-upgrade + nginx -t，視窗即時顯示進度；一次只更新一台、更新中不可部署；節點需安裝 `npm-node-upgrade` 腳本並授權；記入操作紀錄 |
| 遠端重開機 | 節點卡片「重開機」按鈕，需輸入節點名稱確認；部署中、另一台不是 ONLINE、正在更新套件、10 分鐘內重開過時會拒絕；節點 sudoers 需允許 `systemctl reboot`；記入操作紀錄。重開機不會安裝套件，只讓已安裝的更新生效 |
| 後端連線燈號 | 每個後端 IP 前的燈號：綠（全部節點可連）/ 黃（部分）/ 紅（都連不上）/ 灰（未檢測） |
| 從節點測試後端連線 | SSH 到每台節點測試後端 TCP 與 HTTP 狀態碼，可測試尚未儲存的後端 |
| 檢視 Nginx Log | 唯讀讀取節點的 access / error / WAF Log，可關鍵字搜尋、自動更新 |
| 部署紀錄 | 每次部署的即時 Log、結果與錯誤原文 |
| 操作紀錄 | 誰在何時、從哪個 IP 做了什麼；修改只記錄有變動的欄位 |
| 帳號管理 | 維護可登入名單，可停用或刪除 |

## 4. 部署流程與安全機制

### 4.1 兩階段部署

| 階段 | 動作 | 失敗時 |
|---|---|---|
| 0 | 平行連線所有**啟用中**的節點 | 中止，未變更任何節點 |
| 1 | 備份節點上的 `sites-managed` 與 `ssl` 目錄，寫入憑證與設定檔（先寫暫存檔再改名） | 自動回滾 |
| 2 | 所有節點平行執行 `nginx -t` 檢查語法 | **全部節點回滾**，錯誤原文寫入部署紀錄 |
| 3 | 所有節點平行 `systemctl reload nginx` | 狀態標為部分成功（PARTIAL） |

- **核心原則：全部節點 `nginx -t` 通過才 reload，任一台失敗即全部回滾。**
- 部署為「完整鏡像」：停用或刪除的規則、不再使用的憑證會一併從節點清除。
- 同一時間只允許一個部署。
- 停用的節點不參與部署；有網域開啟 WAF 時，任一節點未安裝 WAF 模組會在寫入前中止。
- 部署後的 reload 不中斷既有連線。

### 4.2 設定產生的安全原則

- 所有寫入 Nginx 設定檔的欄位都經過 `validateRule()` **白名單驗證**（網域格式、IP、Port、大小格式、規則 ID 等）。
- 錯誤頁內容在寫入前再檢查一次，不得含引號、`$`、反斜線或換行。
- 不提供自訂 ModSecurity 規則輸入（規則語法可執行外部程式）。
- 自訂 Nginx 語法只檢查大括號成對，正確性由 `nginx -t` 把關。

## 6. 安裝與設定

### 6.1 控制層主機需求

| 項目 | 說明 |
|---|---|
| 作業系統 | Windows Server 2022（亦可 Linux） |
| Node.js | LTS 22 或 24（x64），最低 18.17 |
| PM2 | `npm i -g pm2`；Windows 需搭配 pm2-installer 或 NSSM 註冊為服務 |
| OpenSSL | 上傳 PFX 憑證時使用，需在系統 PATH |
| 對外連線 | SQL Server（1433）、各 Nginx 節點（SSH 22）、學校認證 REST API（HTTPS 443，本機 IP 須在其白名單內） |

### 6.2 安裝步驟

```bash
# 1. 建立資料庫（可重複執行，升級時再跑一次即可補上新欄位）
sqlcmd -S <資料庫主機> -U <帳號> -i database/schema.sql

# 2. 建立設定檔並填入實際值
copy backend\.env.example backend\.env

# 3. 安裝、編譯前端
npm run install:all
npm run build

# 4. 啟動（正式環境）
pm2 start ecosystem.config.js
pm2 save
```

- 系統只使用**一個 port**（`PORT`），前端編譯結果由後端直接提供。
- **只能執行 1 個執行個體**（部署鎖、登入鎖定、即時 Log 都存在記憶體），請勿改為 cluster 模式。
- 正式環境建議以 IIS（URL Rewrite + ARR）或 Nginx 套上 HTTPS 後轉給本系統；即時部署 Log 使用 SSE，代理需關閉回應緩衝。

### 6.3 環境變數（`backend/.env`）

> `backend/.env` 含密碼與金鑰路徑，**不可進版控**；新增設定項目時同步更新 `backend/.env.example`。

| 類別 | 變數 | 說明 |
|---|---|---|
| 服務 | `PORT` | 服務埠 |
| | `TRUST_PROXY` | 前方反向代理的信任清單，用於取得真實登入者 IP |
| 登入 | `ADMIN_ACCOUNTS` | 特權帳號（逗號分隔），至少一個 |
| | `JWT_SECRET` | 至少 32 字元，未設定則拒絕啟動 |
| | `JWT_EXPIRES_IN` | Token 有效時間，例 `8h` |
| | `LOGIN_MAX_FAILURES` / `LOGIN_LOCK_MINUTES` | 連續登入失敗上限與鎖定時間 |
| | `LOGIN_CAPTCHA` / `LOGIN_FAIL_MIN_MS` | 登入圖片驗證碼開關、失敗回應最短時間（防帳號列舉） |
| 帳號認證 | `AUTH_API_URL` | 學校認證 REST API 端點（帳密驗證與姓名 / 單位查詢共用） |
| | `AUTH_API_KEY` | API 金鑰（以 `X-Auth-Key` 標頭送出），向認證服務管理者索取，只放在 `.env` |
| | `AUTH_API_TIMEOUT_MS` / `AUTH_API_TLS_VERIFY` | 逾時（毫秒）、是否驗證憑證 |
| 資料庫 | `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD` | SQL Server 連線 |
| | `DB_ENCRYPT` / `DB_TRUST_SERVER_CERT` | 連線加密設定 |
| SSH | `SSH_KEY_PATH` / `SSH_KEY_PASSPHRASE` | 部署用私鑰（建議 ed25519） |
| | `SSH_CONNECT_TIMEOUT_MS` | 連線逾時 |
| 節點路徑 | `REMOTE_CONF_DIR` / `REMOTE_SSL_DIR` | 設定檔與憑證目錄 |
| | `REMOTE_BACKUP_PATH` / `REMOTE_LOG_DIR` | 部署備份檔、Log 目錄 |
| Nginx | `NGINX_TEST_CMD` / `NGINX_RELOAD_CMD` | 檢查與重新載入指令 |
| | `NGINX_HTTP2_SYNTAX` | `modern`（nginx ≥ 1.25.1）或 `legacy` |
| PROXY protocol | `PROXY_PROTOCOL_FROM` | F5 的來源位址；留空 = 停用 |
| | `PROXY_PROTOCOL_HTTP_PORT` / `PROXY_PROTOCOL_HTTPS_PORT` | 預設 8080 / 8443 |
| 切換前檢查 | `CUTOVER_VIP` | F5 VIP；留空 = 停用此功能 |
| 健康檢查 | `HEALTH_INTERVAL_SEC` | 節點健康檢查週期（秒），0 = 停用 |

## 7. 操作說明

### 7.1 登入

使用學校帳號密碼登入。帳號需同時滿足：

1. 在**可登入名單**內（`.env` 的特權帳號，或「帳號管理」中啟用的帳號）。
2. 通過學校認證 REST API 驗證（本系統不保存任何密碼）。

登入成功後，畫面右上角會顯示由認證服務查得的**姓名與單位**；查無資料時改顯示帳號，不影響登入。

登入時需輸入**圖片驗證碼（四碼數字）**；看不清楚可點圖片換一張。驗證碼只能使用一次，輸入錯誤或超過 3 分鐘會自動換新。

為避免帳號被列舉，帳號不存在、無權限或密碼錯誤一律顯示相同訊息，且失敗回應時間一致。連續登入失敗會暫時鎖定該 IP + 帳號。認證服務本身異常時（例如 API 金鑰未設定或錯誤、本機 IP 不在白名單、請求過於頻繁、服務停用或逾時），登入畫面顯示「認證服務暫時無法使用」，詳細原因記錄在後端 Log 與操作紀錄，請聯絡系統管理者處理。

### 7.2 畫面分頁

| 分頁 | 用途 |
|---|---|
| 網域對照規則 | 新增 / 編輯 / 刪除規則、匯入匯出、測試後端、預覽設定、切換前檢查 |
| SSL 憑證庫 | 上傳 / 續約 / 刪除憑證，查看到期日 |
| Nginx 節點 | 新增 / 編輯節點、讀取主機金鑰指紋、重新檢測、檢視 Log |
| WAF 防護 | 全域總開關、嚴格程度、阻擋門檻、各節點模組狀態 |
| IP 存取控制 | 全域黑名單、IP 群組 |
| 部署紀錄 | 歷次部署結果與 Log |
| 帳號管理 | 可登入名單 |
| 操作紀錄 | 所有操作的稽核紀錄，可依條件查詢 |

### 7.3 常用作業流程

**新增一個網站**

1. 確認憑證庫已有涵蓋該網域的憑證（沒有就先上傳）。
2. 「網域對照規則」→「新增規則」，填來源網域、後端主機，選憑證。
3. 按「從節點測試連線」確認兩台節點都連得到後端。
4. 儲存 → 節點卡片上方的「一鍵同步部署」，看即時 Log 確認成功。
5. 執行「切換前檢查」，結果為「可以切換」後再修改 DNS 指向 F5 VIP。
6. DNS 修改後，以瀏覽器實際開啟網站確認。

**憑證續約**

1. 「SSL 憑證庫」→ 該憑證「續約」→ 上傳新憑證。
2. 「一鍵同步部署」，所有綁定的網域一起更新。

**網站維護**

1. 編輯規則 → 開啟「維護中頁面」→ 部署。
2. 維護完成後關閉 → 部署。

**處理 WAF 誤判**

1. 「檢視 Nginx Log」→「WAF 事件」→ 選該網域，找出被誤擋請求的規則 ID。
2. 編輯該網域規則，在「WAF 排除規則」填入規則 ID → 部署。
3. 注意兩台節點各有自己的 Log，兩台都要查看。

**封鎖攻擊來源**

1. 「檢視 Nginx Log」→「WAF 事件」，在該行按「封鎖」。
2. 選擇範圍（單一 IP 或 /24）與封鎖位置（全域或該網域）→ 部署。

## 8. 安全設計

| 面向 | 做法 |
|---|---|
| 登入認證 | 學校認證 REST API 帳密驗證（HTTPS + API 金鑰，金鑰只存於伺服器設定檔）+ 可登入名單 + JWT；不在名單的帳號回應與密碼錯誤相同，避免帳號被列舉 |
| 暴力破解 | 同一 IP + 帳號連續失敗即鎖定；`TRUST_PROXY` 防止偽造 X-Forwarded-For 繞過 |
| 權限即時生效 | 每次請求重新比對可登入名單，停用帳號立即失效 |
| 設定注入 | 所有寫入 Nginx 設定的欄位經白名單驗證；不開放自訂 WAF 規則 |
| 指令注入 | SSH 指令中的參數一律以單引號跳脫，Log 檔名只接受白名單 |
| SSRF | 切換前檢查只連線規則中的網域、VIP 與已登錄節點，不接受使用者輸入的位址 |
| SSH 中間人 | 可設定節點主機金鑰指紋（SHA256）驗證 |
| 機密保護 | 密碼、PFX 密碼、私鑰不寫入操作紀錄、不出現在 API 回應；WAF 不開 audit log，避免記錄 POST 內容 |
| 節點最小權限 | deployer 只能寫兩個目錄、sudo 只有兩個指令 |
| 版控 | `backend/.env`、私鑰（`*.key`、`*.pem`）、`*.pfx` 不進版控 |

**注意事項**

- 憑證私鑰以明文存於 SQL Server，請限制資料庫存取，建議啟用 TDE 或欄位加密。
- 部署備份檔含私鑰，在節點上的權限為 600。
- 正式環境請以 HTTPS 提供本系統，避免帳密與 Token 以明文傳輸。

## 11. 常見問題排查

| 現象 | 可能原因 | 處理方式 |
|---|---|---|
| 部署失敗並回滾 | 設定語法錯誤、憑證過弱、自訂語法錯誤 | 查看部署紀錄的錯誤原文，修正後重新部署 |
| 部署失敗：too long parameter | 單一參數超過 nginx 4096 bytes 上限 | 系統已自動切段處理；若為自訂語法請縮短 |
| 網站出現 502 / 504 柴犬頁 | 後端沒開、防火牆未開放節點連入、後端回應太慢 | 「從節點測試後端連線」，檢查後端防火牆 |
| 網站出現 404 柴犬頁 | 網域沒有規則或尚未部署 | 確認規則已啟用並部署 |
| 瀏覽器顯示「重新導向次數過多」 | 後端自己強制轉 HTTPS（例如 IIS URL Rewrite 判斷 `{HTTPS}`） | 後端改依 `X-Forwarded-Proto` 判斷，或移除後端的強制轉址 |
| DNS 改完後部分人仍連到舊位址 | DNS 快取尚未過期（依 TTL，例如 30 分鐘） | 等待 TTL 過期，或清除用戶端 DNS 快取 |
| 校內可連、校外不通 | 邊界防火牆未開放 F5 VIP | 請網路管理者開放 VIP 的 80 / 443 |
| 單一電腦連不上，其他人正常 | 本機 hosts 檔寫死舊 IP、DNS 快取 | 檢查 hosts 檔、執行 `ipconfig /flushdns` |
| 節點燈號紅色、時好時壞 | 節點 IP 與其他主機衝突 | 以 `arping` 確認，找出衝突主機並更換 IP |
| 檢視 Log 顯示權限不足 | 節點未設定 ACL | 依畫面提示以 sysadmin 執行 `setfacl` 指令 |
| WAF 誤擋正常功能 | 規則誤判 | 查 WAF 事件找出規則 ID，加入該網域排除清單 |
| 被 403 擋下 | IP 在黑名單或不在只允許清單 | 檢查「IP 存取控制」與網域設定，移除後重新部署 |
| 「切換前檢查」按鈕無法使用 | 未設定 `CUTOVER_VIP` | 設定後重啟服務 |
